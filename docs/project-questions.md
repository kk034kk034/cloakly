# 專案問答

進入專案首頁即可直接問答，不必另開頁面。可以問「登入採用什麼驗證方式？」、「哪次會議決定要加入登入功能？」；詢問整體狀況時會自動優先整理近期資料，也可點「整理目前專案狀況」範例。會議紀錄收成卡片，點開後再瀏覽清單。

## 自動掃描與讀取文件

專案資料夾就是來源範圍，不需要另行選取文件、匯入資料夾或建立副本。首頁不再顯示額外「參考文件」卡片。

1. 將文件放進已選定的專案資料夾或子資料夾即可。提問與建立會議參考內容前會重新掃描支援格式，讀取最新檔案；新增檔案不必手動登錄，移除的檔案不再被使用。
2. 不複製、搬移或修改原檔；以資料夾當下內容為準，不使用舊版本的文件勾選名單。
3. 介面不列出完整檔案清單；每次提問直接依資料夾當下內容重新掃描。

| 格式 | 讀取內容與來源定位 | 限制 |
| --- | --- | --- |
| PPTX | 按簡報實際順序讀取文字、表格文字、講者備忘稿，標示投影片頁碼 | 不含圖片、圖表數值、SmartArt、嵌入物件；最多 300 頁 |
| PDF | 文字層，標示頁碼 | 掃描頁需 OCR，本版未提供 OCR；多欄與表格順序需核對，最多 500 頁 |
| XLSX | 工作表名稱、列號、儲存格位置、公式及快取結果 | 不執行公式，日期可能顯示序號，不套用數字格式或辨識圖表 |
| DOCX | 本文與表格文字，標示段落 | 不含圖片、頁首頁尾；未解讀修訂語意，段落不是列印頁碼 |
| 程式碼／文字 | 常見 Dart、Python、JS/TS、Java/Kotlin、Swift、C/C++、C#、Go、Rust、SQL、HTML/CSS 等及設定檔，保留路徑與行號 | 不執行程式，不代表已測試或已部署；不是全量程式語意索引 |

舊版 `.ppt`、`.xls`、`.doc` 需先另存為新格式；ZIP 原始碼請解壓至專案資料夾。Office／PDF 每檔最多 50 MB，文字／程式碼每檔最多 256 KB。為避免單次提問耗盡記憶體，資料夾掃描設 2,000 份安全上限及 20 層深度上限；到達上限時會明確警示。掃描會排除隱藏檔、依賴套件、鎖定檔、建置產物、符號連結及不支援的二進位檔。

PDF 新增原生 PDFium 依賴，需要重新建置／安裝 App，僅 hot reload 不足以載入。手機端功能和桌面端共用；仍需在實機確認文件選取權限。

## 範圍與來源

- 每個問答頁固定綁定專案 ID，使用其資料夾下可讀取的支援文件，以及此專案已儲存的會議紀錄、定稿逐字稿、現場筆記。未分類與其他專案的會議不會混入。
- 包含該資料夾內的子資料夾；現有資料模型是專案列表，沒有新增父子專案或跨專案會議彙整。
- 每次提問重新讀取資料，依英文詞與中文雙字片段檢索；第一版是本機關鍵字 RAG，不使用 embeddings，改用不同同義詞可能找不到。
- 文件依行切段，長行保留尾段；逐字稿會保留相鄰發言，便於找到負責人及期限。最多提供 16 個片段，對不同文件與會議保留名額。
- 點回答的 `[S1]` 或來源列可查看提問當時的文字片段、文件行號或逐字稿時間；會議來源可再開啟完整會議。這不是音訊播放器的自動跳轉。
- 超過格式大小限制、非 UTF-8 文字、遺失、加密、損毀或解析後超出專案資料夾的文件會略過並顯示原因。無文字層的頁面會提示未辨識，不會當成已讀完。

## 回答限制

每題獨立檢索，不使用先前對話作為依據。問答只保留在目前頁面，離開後清除。未命中時不呼叫 AI，也不代表歷史上沒有討論過；可改用具體功能名稱。

現況總覽優先近期片段，並非任務資料庫或即時專案狀態。要求 AI 區分提案、承諾、已確認與待確認事項，列出資料日期及衝突，不能因期限已過就認定完成。檔案修改時間不等於決議生效時間。來源 ID 會驗證，但引用內容是否真正支持每個結論仍需人工核對。

「目前專案進度」「做到哪裡」等問句會自動採現況總覽，並為文件與會議各保留檢索名額。簡報提供背景或計畫，逐字稿提供口頭報告及後續更新；只有內容有明確對應才可連結，不能假定一場會議一定使用某份 PPT。已有音檔但沒有定稿逐字稿時會警示，本版不會重新轉寫歷史音檔，也不會憑程式碼存在推論已上線。

手機問答提示已更新以處理這些來源；請依下方指令重新部署 `project-question`（既有 endpoint 可以直接更新）。無需新增資料表或金鑰。

專案首頁上方直接呈現「專案狀態」與「會議紀錄」卡片；狀態可點進甘特圖，會議紀錄另開清單頁。中段為專案問答（Enter 送出、Shift+Enter 換行）；最下方整條「開始會議」方便拇指操作。甘特圖／階段看板改由 AppBar 或狀態卡進入。工作依階段拆分，每個階段建議維持少數可完成項目；看板與時間軸只顯示目前檢視的階段。階段內工作全部移到「完成」後可封存，已封存階段收合在列表底部不佔版面。也可請 AI 依文件與會議建議分階段時程，審核後才寫入。專案列表首頁先顯示「全部專案看板」，其下才是「選擇專案」列表，兩者標題同級；看板只彙整各專案現行未封存階段的工作。

專案回答、即時回答提示、會議紀錄及其他 AI 功能會顯示 API 回傳的 token 用量與估計費用。台幣以固定 `1 USD = 31.8 TWD` 顯示估值，實際帳單以供應商與信用卡匯率為準。

## AI 與部署

桌面版沿用自備 OpenAI 金鑰；手機版使用新增的 `project-question` 與 `project-plan` Edge Functions。相關文字片段會送往 AI 服務，不是離線生成。沒有設定 AI 時不會產生示範答案冒充專案資訊。

手機後端沿用既有 `requireUser` 與 `requireHostedAccess`，需要登入，且具有效 Pro 權益或符合既有當日會議額度授權。這一版未改變訂閱規則。

### 部署到既有 Supabase 專案

函式程式碼及 `config.toml` 已建立，不需要在 Dashboard 手動新增空白函式。Windows PowerShell 先切到 `backend`（裡面有 `supabase/config.toml`），使用 Node.js 20 以上的 npx 執行 CLI：

```powershell
Set-Location C:\Kate\sideProject\cloakly\backend
npx --yes supabase login
npx --yes supabase functions deploy project-question --project-ref svqecjahbnjylhlewnyw --use-api
npx --yes supabase functions deploy project-plan --project-ref svqecjahbnjylhlewnyw --use-api
```

上面的 project ref 來自本工作區既有的 `supabase/.temp/project-ref`；部署其他環境時需換成該環境的 ref。已登入可略過 login。`--use-api` 不需要本機 Docker。

既有會議摘要若已正常運作，就沿用同一組伺服器端 `OPENAI_API_KEY`，無須新增金鑰。尚未設定時，至 Supabase Dashboard → Edge Functions → Secrets 新增 `OPENAI_API_KEY`；不可放進手機設定檔。

部署完成後，可在 Dashboard 的 Edge Functions 列表看到 `project-question`，或執行：

```powershell
npx --yes supabase functions list --project-ref svqecjahbnjylhlewnyw
```

重新執行／安裝包含專案問答頁的手機版，登入後在有文件或會議資料的專案提問。若回傳 401，重新登入；若回傳 `MEETING_ALLOWANCE_REQUIRED`，表示既有 Hosted AI 權益檢查未通過；若為 404，確認部署專案與手機 `SUPABASE_URL` 指向同一環境。此函式在 handler 內驗證登入，請保留已提交的 `verify_jwt = false` 設定。

本機改程式不會自動部署 Hosted endpoint，也不會替使用者建立雲端索引。無資料庫 schema 變更。

## 驗證

```powershell
cd packages/cloakly_core
flutter test
```

專案問答測試涵蓋跨專案會議隔離、資料夾自動發現文件、中文檢索、長文件尾段、相鄰發言、暫定逐字稿排除、近期資料排序、缺漏資料夾、引用 ID 驗證及問答畫面成功／失敗／離開處理。

```powershell
deno test backend/supabase/functions/_shared/project_question_test.ts
```

此測試檢查手機問答 payload 的來源結構與輸入上限，不代表已驗收真實模型回答品質。
